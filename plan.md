# Logbook — implementation plan

Tracks the gap between `design.md` and the plugin implementation (`plugin/`). All phases below are complete and verified (`tsc -noEmit` + `esbuild` after every change).

## Status: done

- **Phase 0 — File layout.** Split the original single-file prototype into `main.ts`, `settings.ts`, `types.ts`, `note-store.ts`, `filters.ts`, `utils.ts`, and `view/{LogbookView,feed,card,pickers,dock}.ts`.
- **Phase 1 — Data layer.** Stable per-note `id`; frontmatter reads centralized through the metadata cache; per-file `processFrontMatter` write queue; 600ms refresh-suppression window with a settle-resync callback; `LogNote` discriminated union covering all type-specific fields.
- **Phase 2 — Note types.** All six types (Draft, Task, Meeting, Thoughts, Knowledge, Design) implemented with their type-specific fields, including filterable attributes (status, theme, techStack).
- **Phase 3/4 — Card UI.** Collapsed and expanded card views: status pills, project/team pickers, editable title (via `renameFile`), type-specific fields, `⌘↵`/`Esc` handling, debounced autosave through the write queue.
- **Phase 5 — Feed behavior.** Day-group labels (Today/Yesterday/weekday/date), one-month initial window with scroll-triggered pagination, full-vault search when filters are active, dual empty states, scroll-to-new-note on creation.
- **Phase 6/7 — Command bar.** Full `/` command set: creation commands (including `/done`, `/recurring`, `/thoughts`), filter commands (`/project`, `/team`, `/type` with two-step sub-attribute picking, `/occurrence`, `/clear`), filter chips with priority-ordered `Backspace` removal, fuzzy matching throughout.
- **Phase 8 — Filtering engine.** AND-combined filter state (free text, projects, teams, type, type-attribute) with `<mark>` highlighting on matches.
- **Phase 9 — Meeting specifics.** Recurring meetings (`## <date>` headings mirrored in `occurrences[]`), template notes (`type: template`, discovered via frontmatter scan, excluded from the feed), template scaffolding applied on standalone creation and on new occurrences.
- **Phase 10 — Lifecycle.** Draft auto-delete after 7 days (via trash, never hard delete); collapse-mode toggle; settings tab.
- **Phase 11 — Polish pass.** Keyboard shortcuts audited against the design doc; live refresh suppression verified; anti-feature checklist (§13) confirmed clean.
- **Phase 12 — Design revision (2026-06-20).** `design.md` was revised on four points; all implemented and verified, including live-vault QA:
  1. Expanded cards no longer render the full body — only the same plain-text preview shown collapsed. Full content is read/edited exclusively in Obsidian's own editor.
  2. Dropped the plugin-managed `updatedAt` field; the feed's sort key and time pills now read `file.stat.mtime` directly, so out-of-plugin body edits reorder the feed too.
  3. Removed the plugin's entire tag system (picker, chips, filter axis, click-to-filter). Tags are Obsidian's native feature now — the plugin doesn't touch them.
  4. Removed "New task from this note" (and `sourceNoteId`) entirely, no replacement.
- **Phase 13 — Stable position while expanded (2026-06-20).** Frontmatter-only edits (status pill, project/team changes) bump `file.stat.mtime` exactly like body edits, which was reordering the feed out from under an open card. Fixed in `LogbookView.ts`: the expanded card's sort key is frozen at the timestamp it had when expanded, and only resumes tracking live `mtime` once it collapses.
- **Phase 14 — Card layout redesign (2026-06-20).** `design.md` §4, §5.2, §5.3, §5.5, §7, §8, §9, §14, §15 revised: collapsed cards now show the filterable-property pill and project/team pills (briefcase/people icons) in the top row, with the title moved to the middle and the 2-line body preview at the bottom; expanded cards keep only the badge top-left and move every other pill/field into the field block. Meeting's filterable attribute changes from `theme` to `subtype`; knowledge's `techStack` is no longer filterable. Implemented in `types.ts` (filterAttr changes), `LogbookView.ts` (`typeAttrValues`/`CardContext.onFilterType`), `pickers.ts` (icon support), `card.ts` (relocatable `pillsRow` DOM node moved between collapsed top row and expanded field block via `insertBefore`), and `styles.css`. Verified with `tsc -noEmit -skipLibCheck` + `node esbuild.config.mjs production`; committed.

- **Phase 15 — Auto-open note on expand (2026-06-20).** `design.md` §4, §5.3, §6, §13 revised: expanding a card no longer shows a body preview or an "Open note →" button — instead, the act of expanding now also opens the underlying note in Obsidian's native editor automatically, same destination/pane behavior the button used to trigger. The body preview remains collapsed-card-only. Implemented: `card.ts`'s `expand()` now calls `ctx.app.workspace.openLinkText(...)` directly; the `openBtn` element/listener and `.logbook-open-btn` CSS were removed; `.logbook-card.is-expanded .logbook-card-preview-wrap` is hidden via CSS.
- **Phase 16 — One line per pill type, simplified add affordance (2026-06-20).** `design.md` §4 revised: in the expanded card, the filterable-property pill and the project/team pills each render on their own line with the pill type's name (`Status`/`Subtype`, `Projects`, `Teams`) as a label on the left, matching the other type-specific field rows. The project/team "+ project"/"+ team" always-visible text input was replaced with a plain `+` button that reveals an autofocused input on click and collapses back to `+` on blur/`Esc`, staying open across consecutive adds. Implemented in `card.ts` (new `renderPillLine()` helper wrapping the filter-attribute pill / project row / team row, each as a `.logbook-pill-line` with a `.logbook-pill-line-label`), `pickers.ts` (`open()`/`close()` toggle between a `.logbook-picker-add-btn` and a `.logbook-picker-input-wrap.is-open`, `render(values, keepOpen)` re-opens after an add), and `styles.css` (`.logbook-pill-line` is `display: contents` with a hidden label while collapsed — so the collapsed top row layout is unchanged — and becomes a labeled flex row once relocated into `.logbook-card-expand-inner`).

- **Phase 17 — Incremental feed rendering (2026-06-20).** `design.md` §15 revised: the feed no longer tears down and rebuilds every card on every refresh (previously `renderFeed()` called `feedEl.empty()` and recreated every divider and card on each call — and a settle-triggered refresh fires ~600ms after *any* `processFrontMatter` write anywhere in the vault, so essentially every interaction caused a full-feed rebuild shortly after its own immediate local DOM patch, which read as a visible flicker). Implemented: `card.ts` gained `buildCard(note, ctx)`, a thin wrapper around the existing (unchanged) `renderCard()` that builds the card detached from any parent and returns the element. `feed.ts`'s `renderFeed()` now takes a `CardCache` (`Map<path, {el, sig}>`, owned by `LogbookView` so it survives across renders) and, per note, computes a signature from `[note.fm, note.body, note.file.stat.mtime, searchQuery]`; if a cached card exists with a matching signature — or the note is currently expanded (`cardCtx.isExpanded`), regardless of signature, so an active edit session is never disturbed by unrelated changes — the existing DOM node is reused as-is. Top-level children of `feedEl` (dividers + cards) are reconciled in place via a keyed `reconcileChildren()` (single-pass `insertBefore` walk, only removing nodes absent from the new desired list) instead of `feedEl.empty()`, so unchanged cards are never even detached from the DOM — no blur, no lost input focus/scroll position. Only a note whose own data actually changed gets its card rebuilt; everything else is left untouched.

- **Phase 18 — Save-on-close, global `Mod+Enter`, top-right pin fix (2026-06-20).** `design.md` §4 and §15 revised: expanded-card edits (title, filterable-property pill, project/team pills, type-specific fields) no longer write to disk per keystroke/click — they stage locally and flush in one batch the moment the card closes; `Esc` discards staged edits by re-reading the note's (still-unwritten-to) frontmatter and re-rendering the card. `⌘↵`/`Mod+Enter` is now a plugin-level command (global hotkey) rather than a card-scoped `keydown` listener, since expanding a card auto-opens the note in Obsidian's editor and moves focus there, so a listener on the card's own DOM never saw the keystroke. Also fixed: the chevron/age pair drifted left when a card expanded (it was relying on the now-relocated pills row's `flex:1` as a spacer) — pinned via `margin-left: auto` on `.logbook-chevron` instead. Implemented:
  - `card.ts`: every field handler (title input, theme/question/landed/template inputs, status-pill cycle, project/team/attendee/techStack pickers) now mutates `note.fm` + the field's own DOM immediately (unchanged) but no longer calls `ctx.store.*` itself. A `dirty: Set<string>` plus `titleDirty`/`templateDirty` flags track what changed; `commit()` flushes them as one `renameTitle` (if title changed), one `setMeetingTemplate` (if template changed), and one batched `updateFrontmatter` call covering every other dirty key. The `Escape` handler calls a new `ctx.discardEdits(path)` instead of hand-reverting each field. `expand()` now registers a force-close callback `closeAndSave` (`commit()` then the existing collapse-UI logic) via `ctx.expand(path, closeAndSave)`.
  - `LogbookView.ts`: `CardContext.expand` takes the force-close callback and stores it as `activeCloseHandler`; switching to a different card invokes the previous card's own handler — replacing the old `querySelectorAll(".is-expanded").forEach(el => el.classList.remove(...))` DOM-only bypass, which never ran the previously-open card's own collapse logic (so its pills row stayed stranded in the expanded position). Added `discardEdits(path)`: reloads all notes from disk via `store.loadNotes()` (disk-truth is still the pre-edit state, since nothing was written), evicts the one path from `cardCache` so `feed.ts`'s diff rebuilds only that card, and clears `expandedPath`. Added a public `closeActiveCard()` that invokes `activeCloseHandler` if set.
  - `main.ts`: registers a new command (`id: "close-logbook-card"`, default hotkey `Mod+Enter`) that calls the new public `LogbookView.closeActiveCard()` on every open Logbook leaf, looked up via `getLeavesOfType(VIEW_TYPE_LOGBOOK)`.
  - `styles.css`: `.logbook-chevron`'s `margin-left: 0` → `margin-left: auto`.
  - **Bug fix (same day):** a card that starts out already-expanded — i.e. a freshly created note, where `LogbookView.createAndShow` sets `expandedPath` directly rather than through `ctx.expand` — never ran through the `expand()` closure that registers `closeAndSave` as `activeCloseHandler`. So `Mod+Enter` silently did nothing for a brand-new note, and expanding a different card while it was open skipped its commit/collapse entirely, leaving it visually stuck `is-expanded` (pillsRow stranded in the expanded position) while another card also showed expanded — read as "weird ordering" since two cards appeared open/shifted at once and the unsaved edits vanished. Fixed by adding `CardContext.registerCloseHandler(path, fn)` — sets `activeCloseHandler` only if `path` is still the expanded one, without touching `expandedPath`/`frozenTimestamp` or force-closing anything — called from `card.ts` whenever a card renders already-expanded (the same `if (isExpanded) { ... }` block that repositions `pillsRow` on initial render).

- **Phase 19 — ⌘↵/Esc reliable while focus is inside a card's own fields (2026-06-20).** `design.md` §4 revised: the user reported that `Mod+Enter` (added in Phase 18 as a global hotkey only) still didn't fire while focus was inside the card's title input or a property field. Root cause, concretely verifiable for picker-backed fields (projects/teams/attendees/techStack): `pickers.ts`'s own `keydown` listener on its `<input>` unconditionally treated plain `Enter` as "add this value" and called `stopPropagation()` regardless of modifier keys, swallowing `Cmd/Ctrl+Enter` before it could bubble anywhere. For plain inputs (title, theme, question, landed, template) the exact cause couldn't be fully confirmed without live testing, but the fix applied is the same either way and removes the dependency on bubbling entirely. Implemented:
  - `card.ts`: `commit`/`collapseUI`/`closeAndSave` (unchanged in behavior) moved earlier in `renderCard()`, and a new `onFieldKeydown` closure defined alongside them (`Cmd/Ctrl+Enter` → `closeAndSave()`, `Escape` → `ctx.discardEdits(path)`, both with `preventDefault`/`stopPropagation`). Attached directly via `addEventListener("keydown", onFieldKeydown)` on `titleInput` and (via a new 6th parameter on `renderTypeFields`) on `themeInput`, `templateInput`, `qInput`, and `lInput`. The old card-level `keydown` listener remains as a fallback for non-input elements (e.g. a pill).
  - `pickers.ts`: the input's `keydown` handler now returns immediately on `Enter` held with `metaKey`/`ctrlKey`, leaving it alone to bubble up to the card's listener instead of treating it as "add value". Its `Escape` handling no longer calls `stopPropagation()`, so the card's own discard-on-Esc still fires for picker-focused fields too.

- **Phase 20 — Relative-time pill no longer frozen on a reused card (2026-06-20).** `design.md` §15 revised: reported as "creating a recurring meeting now sorts to the bottom of the day as expected, but the time pill still says 'now'" even after time had passed. Root cause: Phase 17's incremental rendering keys each card's cache entry on a signature of `[note.fm, note.body, note.file.stat.mtime, searchQuery]` — none of which change just because wall-clock time passes — so a card that's reused unchanged across renders kept showing whatever relative-time text (`"now"`, say) was current the last time it was actually rebuilt, indefinitely, until something about the note itself changed. Fixed in `feed.ts`'s `resolveCard()`: on a cache hit, the reused element's `.logbook-time` text node is still refreshed with a freshly computed `relativeTime(note.file.stat.mtime)` before returning it, even though the rest of the card DOM is left untouched.

- **Phase 21 — Recurring meeting still sorting to the top of today's group (2026-06-20).** `design.md` §3 revised: Phase 17/20's fixes didn't address the actual root cause behind "recurring meeting shows at the top of the day, not the bottom" — `activityTimestamp()` (`types.ts`) used a recurring meeting's latest-occurrence **date only** (e.g. `"2026-06-20"`, no time-of-day) as its sort key whenever `occurrences` was non-empty. A bare date parses to local midnight, which is earlier than every other note's real same-day `file.stat.mtime` — so a recurring meeting touched seconds ago still sorted as if it happened at 00:00, pinning it above every other note from today regardless of how recently it was actually edited. There was also a latent, separate timezone bug in the same function: the bare `new Date("YYYY-MM-DD")` constructor parses date-only strings as UTC midnight, which can land on the wrong local calendar day depending on the user's offset. Fixed in `types.ts`: added `localDateFromISO()` (parses `y`/`m`/`d` components directly into a local-midnight `Date`, sidestepping the UTC-parsing bug), and `activityTimestamp()` now only uses the occurrence-date timestamp when that occurrence is *not* today — when it is today, it falls back to `file.stat.mtime` (which already reflects the real edit time and sorts correctly among today's other notes).

- **Phase 22 — New-note creation didn't collapse the previous card or open the editor (2026-06-20).** `design.md` §4 revised: reported as two bugs on creating a note from the command bar — the previously-expanded card stayed expanded instead of collapsing, and the new note didn't open in Obsidian's editor. Root cause: `LogbookView.createAndShow` sets `expandedPath` directly (so the new card renders already-expanded) rather than going through `ctx.expand()`, which is the only place that both (a) invokes the previously-expanded card's own `activeCloseHandler` (commit + collapse-UI) when switching cards, and (b) calls `openLinkText` to open the note. Fixed in `LogbookView.ts`'s `createAndShow`: now calls `this.activeCloseHandler()` (if set) before creating the file, exactly mirroring what `ctx.expand()` does when switching between two existing cards, and calls `this.app.workspace.openLinkText(file.path, "", false)` after `refresh()`, mirroring what `card.ts`'s own `expand()` does.

- **Phase 23 — Delete button on the expanded card (2026-06-20).** `design.md` §4 revised: added a trash-bin button, pinned to the bottom-right corner of the expanded card's footer, that soft-deletes the note (`app.vault.trash()`, the same never-hard-delete mechanism as draft auto-delete, §5.1). Requires two clicks — the first arms the button (red fill, `is-armed`, for 3s) without deleting anything; a second click while armed deletes; anything else just lets the 3s timeout disarm it. Implemented:
  - `note-store.ts`: new `deleteNote(file: TFile)` — thin wrapper over `app.vault.trash(file, true)`.
  - `card.ts`: new `deleteNote(path)` entry on `CardContext`; `expandFooter` (already a flex row whose `.logbook-kbd-hint` has `margin-right: auto`, pushing anything after it to the far right — no new layout needed) gains a `setIcon(..., "trash-2")` button with the arm/disarm click handling described above, calling `ctx.deleteNote(note.file.path)` on confirm.
  - `LogbookView.ts`: new private `deleteNote(path)` — clears `expandedPath`/`frozenTimestamp`/`activeCloseHandler` if that path was the expanded one (mirroring `discardEdits`'s cleanup, since deleting discards any staged edits outright — there's nothing to commit), evicts the path from `cardCache`, then calls `store.deleteNote(file)`. The card's actual removal from the feed is left to the existing vault `delete` event handler (registered in `onOpen`), not handled specially here.
  - `styles.css`: `.logbook-delete-btn` (ghost icon button, `--text-error` on hover) and `.logbook-delete-btn.is-armed` (solid red fill).

Everything above is implemented, type-checked, and built; manual QA in a live vault (editing several fields then closing via click-away/⌘↵/switching cards and confirming one batched write; `Esc` discarding correctly; ⌘↵ and Esc firing while focus is in the title/property fields themselves as well as while focus is in the opened note's editor; chevron/age staying put on expand; relative-time pills advancing on cards that aren't otherwise changing; a newly created/edited recurring meeting landing at the bottom of today's group; creating a note collapsing/saving whatever card was previously open and opening the new note's editor; the delete button's two-click arm/confirm flow and the card actually disappearing from the feed afterward) is still outstanding since this is a headless session.
