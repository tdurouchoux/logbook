# Logbook — implementation plan

`design.md` is the spec; this file tracks implementation status against it and calls out notable bugs found along the way, rather than a chronological diary of every change. Everything below is implemented and verified via `tsc -noEmit -skipLibCheck` + `node esbuild.config.mjs production`, run from the repo root (there is no `plugin/` subdirectory, despite older wording elsewhere suggesting one).

## Status: done

The full spec is implemented: all eight note types (draft/task/meeting/recurring/thoughts/knowledge/design/daily — design is deprecated but still fully supported for existing notes, see below); the whole feed (day grouping, pinned section, incremental/cached rendering, scroll-triggered history pagination, two-pass search — fuzzy on short fields, substring on body — with match highlighting and a per-card relevance dot since matches never reorder the feed, empty states); the full card lifecycle (save-on-close field staging, "Change type" conversion, pin toggle, soft-delete with arm/confirm); the complete `/` command bar (all creation + filter commands, saved views, `/occurrence`, `/daily`, `/exclude`); the settings tab (logbook folder, per-type templates, draft/done-task TTLs, daily idle threshold, saved views, MCP toggle); and a read-only MCP server exposing the logbook to external agents.

**Architecture patterns worth knowing before touching this code:**

- **Per-file write queue** (`note-store.ts`'s `updateFrontmatter`) — `processFrontMatter` has documented races on rapid/concurrent calls to the same file; every frontmatter write is serialized per path through a promise chain.
- **Refresh suppression** — a write's vault events fire immediately and would otherwise tear down an open card mid-edit; a 600ms per-path suppression window (`isAnySuppressed`/`onSettled`) prevents that.
- **Save-on-close** — an expanded card's field edits only mutate in-memory `note.fm` and the card's own DOM; nothing hits disk until the card closes (`⌘↵`, the Save button, click-away, or switching cards), as one batched write. `Esc` discards by re-reading disk-truth for that one card.
- **Sort-key/section freezing while expanded** — a card holds its feed position, day-group, and pinned/unpinned section for as long as it's open, so a frontmatter edit mid-view can't reorder or relocate it out from under the user.
- **Incremental feed rendering** — cards are cached by path plus a data signature (`feed.ts`); a refresh only rebuilds a note's card if its own data actually changed, and never rebuilds a currently-expanded card regardless of what changed elsewhere.
- **Daily notes bypass the generic creation path entirely** — one note per calendar day at a deterministic `<folder>/<YYYY-MM-DD>.md` path rather than a title slug, found/created via `ensureDailyNote()`/`appendDailyItem()` rather than `createNote()`. Frontmatter deliberately omits `projects`/`teams` (the only type that does), and nothing creates the note automatically — only `/daily` does.
- **Deprecating a type** (`NoteTypeConfig.deprecated`, currently only `design`) closes every *creation* surface — the `/` dropdown, the command palette, "Change type"'s target list, the Templates settings section — while leaving normalization, rendering, and filtering completely untouched, so existing notes of that type keep working exactly as before.

## Notable bugs fixed along the way

- **"Already expanded" bypass paths keep breaking invariants `ctx.expand()` normally enforces.** A card rendered already-expanded (just created, or a programmatic "jump to this note") skips `ctx.expand()` entirely, so anything it relies on has to be re-registered by hand: notes created before `registerCloseHandler` existed silently broke `⌘↵`/switching-cards; `createAndShow()` originally set `expandedPath` directly without closing/saving whatever card was previously open. Worth re-checking any time a new "programmatically open/switch to a note" path gets added.
- Recurring meetings sorted to the top instead of the bottom of "Today" — `activityTimestamp()`'s occurrence-date sort key used bare local midnight, always earlier than same-day notes' real `mtime`. Fixed with a same-day fallback to `mtime` (and a latent UTC-vs-local date-parsing bug caught in the same pass).
- `pickers.ts` unconditionally swallowed plain `Enter`, breaking `⌘↵`/`Esc` on any picker-backed field (project/team/attendee/tech-stack) regardless of the modifier-aware handler already attached above it.
- `/type`'s second step relied on a sticky `pendingType` field only ever set from the dropdown's own click handler — typing the type name by hand instead of clicking left it null or stale. Fixed by re-deriving the type/attribute split from the literal input text on every keystroke rather than trusting carried-over state.
- The search bar's plain-text `Enter` handler created a draft (`onCreate("draft", val)`) instead of searching, despite the spec already saying free text never creates a note.
- The daily-note status bar's pop animation compared today's note's *path* to the previous check, meant to skip animating a fresh day's first render — but "no note" (`undefined`) and "a note exists" (a real path) never compare equal, so the 0→1 transition (the day's actual first log, the most rewarding moment) never animated either. Fixed by comparing logged-item counts alone.
- Search matched almost everything once a query touched `body`: `matchesQuery` ran the fuzzy *subsequence* matcher (`prepareFuzzySearch`, meant for short strings like filenames) against `title` + `body` + `projects` + `teams` + type fields joined into one long haystack, and only checked truthiness, never score. Over paragraph-length text, a short term's letters are almost always found *somewhere* in order, so real queries returned mostly false positives. Fixed by splitting the haystack: fuzzy matching stays on the short, filename-like fields (`shortFieldsOf` — title/projects/teams/type-specific fields), while `body` is matched via plain case-insensitive substring instead, mirroring how Obsidian's own full-text search pane behaves (a different, token/substring-based algorithm from the quick switcher's fuzzy matcher). Preview highlighting (`fuzzyMatchRanges` vs. the new `substringMatchRanges`) was split the same way so highlighted ranges match how the note actually matched.

## Known gap

No migration tooling exists for the pre-Phase-27 meeting schema (`type: meeting`, `subtype: recurring`, plus `theme`/`template`). Such a note now loads as a plain (non-recurring) meeting with agenda defaulted to `meetup` and its old fields silently dropped; a `type: template` marker note loads as a `draft`. Anyone with such notes in their vault needs to manually re-create them as `type: recurring` (and re-tag former templates) after upgrading.

## Outstanding manual QA

This has been a headless session throughout — every change above is verified by `tsc`/`esbuild` only, never exercised in a live Obsidian vault. Worth checking first: the full save-on-close flow (all four ways to close a card) and keyboard shortcuts from both card fields and the opened note's editor; change-type round-trips across all eight types; the pinned section surviving filters and the history-window cutoff; `/daily`'s on-demand creation, no-navigation append, and the status bar's three states plus pop animation end-to-end; the MCP server's five tools round-tripping over Streamable HTTP; and that a note with pre-existing `type: design` frontmatter still renders, filters, and edits identically now that the type is deprecated.
