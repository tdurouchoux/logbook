# Logbook — implementation plan

`design.md` is the spec; this file tracks implementation status against it. Everything below is implemented and verified (`tsc -noEmit -skipLibCheck` + `node esbuild.config.mjs production` after every change, run from `plugin/`).

## Status: done

**Foundational work (Phases 0–11):** file layout split into `main.ts` / `settings.ts` / `types.ts` / `note-store.ts` / `filters.ts` / `utils.ts` / `view/{LogbookView,feed,card,pickers,dock}.ts`; data layer (stable per-note IDs, metadata-cache-backed reads, per-file `processFrontMatter` write queue, 600ms refresh-suppression window); all six note types with their type-specific fields; collapsed/expanded card UI; feed behavior (day groups, scroll-triggered pagination, full-vault search under filters, empty states); full `/` command bar (creation + filter commands, fuzzy matching); AND-combined filter engine with `<mark>` match highlighting; recurring meetings (`## <date>` headings mirrored in `occurrences[]`) and meeting templates; draft auto-delete via trash; collapse-mode toggle; settings tab.

**Since then, `design.md` has been revised and re-implemented several times:**

- **Phase 12** — dropped inline body rendering on expand (preview-only; full content lives in Obsidian's editor), dropped the plugin-managed `updatedAt` field in favor of `file.stat.mtime`, removed the plugin's whole tag system (native Obsidian tags now), removed "new task from this note".
- **Phase 13** — froze an expanded card's sort key at its mtime-on-expand, so a frontmatter edit (status pill, project change) can't reorder the feed out from under an open card.
- **Phase 14** — card layout redesign: collapsed cards show the filterable-property pill + project/team pills in the top row with title/preview below; expanded cards relocate everything but the badge into the field block. Meeting's filterable attribute became `subtype`; knowledge's `techStack` is no longer filterable.
- **Phase 15** — expanding a card now also opens the note in Obsidian's editor automatically; dropped the separate "Open note" button and the inline body preview while expanded.
- **Phase 16** — filterable-property/project/team pills each get their own labeled line when expanded; project/team adding collapsed to a `+` button that reveals an autofocused input.
- **Phase 17** — incremental feed rendering: cards are cached by path + a data signature and only rebuilt when their own note actually changed; top-level DOM is reconciled in place instead of torn down every refresh.
- **Phase 18** — save-on-close: field edits stage in memory and flush as one batched write when a card closes (`⌘↵`, click-away, or switching cards); `Esc` discards staged edits. `⌘↵` added as a global `Mod+Enter` command since focus usually moves into Obsidian's editor on expand. Bug fix: cards that start out already-expanded (e.g. freshly created notes) need `CardContext.registerCloseHandler` too, or `Mod+Enter`/switching cards silently skipped them.
- **Phase 19** — `⌘↵`/`Esc` now also work via per-field `keydown` listeners (title, every plain input, every picker input), not just the global hotkey/bubbling — `pickers.ts` was unconditionally swallowing plain `Enter` regardless of modifiers, breaking the shortcut on picker-backed fields.
- **Phase 20** — relative-time pills no longer freeze on a reused/cached card; refreshed every render pass regardless of cache hit, since wall-clock time isn't part of the cache signature.
- **Phase 21** — fixed recurring meetings sorting to the top instead of the bottom of "Today": `activityTimestamp()` used the latest occurrence's bare date (local midnight) as the sort key, always earlier than same-day notes' real `mtime`. Now falls back to `mtime` when the latest occurrence is today; also fixed a latent UTC-vs-local date-parsing bug in the same function.
- **Phase 22** — creating a note now collapses/saves whatever card was previously open and opens the new note in Obsidian's editor, mirroring what `ctx.expand()` already does when switching between two existing cards (creation was bypassing it by setting `expandedPath` directly).
- **Phase 23** — added a soft-delete (trash) button to the expanded card's footer, bottom-right; two clicks required (arm, then confirm within 3s) before `app.vault.trash()` is called.

Manual QA in a live vault is still outstanding since this is a headless session — in particular: the full save-on-close flow (click-away / `⌘↵` / switching cards / `Esc`), keyboard shortcuts firing from inside both card fields and the opened note's editor, layout stability on expand, time-pill/sort-order correctness for recurring meetings, and the new delete button's confirm flow and follow-through.

## Status: done — Phase 24 (Save button, change type, pinned)

Three additions specced in `design.md` (§2, §3, §4, §12, §14, §15), now implemented (`tsc -noEmit -skipLibCheck` + `node esbuild.config.mjs production` clean from `plugin/`):

- **Save button** — `card.ts`'s `expandFooter` gained a `.logbook-save-btn` that calls the existing `closeAndSave()`. Footer order: hint, Change type, Save, Delete (Delete stays rightmost).
- **Change type** — `types.ts` exports `convertType(fm, toType)` (common fields preserved, old type-specific fields dropped, new type's defaults filled in, mirroring `createNote()`). `note-store.ts` gained `changeType(file, newFm)`, a replace-not-merge write (deletes keys absent from `newFm`, then assigns) routed through the same per-file write queue. `card.ts`'s Change-type button opens an Obsidian `Menu` (chosen over a custom dropdown to avoid clipping from `.logbook-card-expand-inner`'s `overflow: hidden`) listing the other five types by name; picking one calls `convertType`, reassigns `note.fm`, sets a new `typeDirty` flag, and calls `refreshTypeDependentUI()` — a function consolidating every type-dependent DOM piece (badge, `--card-type-color`, `is-done`/`is-suspended`, filter-attr pill line, thoughts' question line, meeting's occurrence-info, knowledge's stack-row, `typeFieldsEl`) so it can be repainted in place without a full card rebuild. `commit()` special-cases `typeDirty` to call `store.changeType` instead of the normal key-by-key `updateFrontmatter`.
- **Pinned** — `types.ts`'s `CommonFrontmatter` gained `pinned?: boolean` (omit-when-absent); `note-store.ts`'s `normalizeFrontmatter` reads it. `card.ts` added a `.logbook-pin-indicator` glyph (pin icon) in the top-right corner cluster, ahead of the chevron — pure indicator while collapsed (CSS-hidden entirely when not pinned), a clickable toggle while expanded that stages `note.fm.pinned` into the normal `dirty` set. `LogbookView.ts` added `frozenPinned`/`isPinnedFor()` (mirroring `frozenTimestamp`/`sortKey()`) so a mid-edit pin toggle doesn't move a card between sections until it collapses; `windowedNotes()` now excludes pinned notes, a new `pinnedNotes()` returns them (filtered but not window-cutoff-limited), and `hasMoreHistory()` excludes them from the cutoff check. `feed.ts`'s `FeedRenderOptions` gained `pinnedNotes`, rendered as one flat list (no day sub-grouping) under a single "Pinned" divider after the regular day groups, with pinned paths added to `livePaths` so the cache-pruning loop doesn't evict them every render.

Also fixed a design.md wording inaccuracy: the Change-type footer bullet said the menu shows "each type's badge color dot" — corrected to reflect the actual Menu-API-based, dot-less implementation (matching `dock.ts`'s own dot-less `/type` list).

## Status: done — Phase 25 (command bar cleanup: dropped `/done`, added `/tag`, fixed `/type`)

- **Dropped `/done`** — removed the creation shortcut for logging an already-finished task. `dock.ts` no longer lists it in the command dropdown or handles it on `Enter`; `LogbookView.ts`'s `createAndShow` lost its `done` option; `note-store.ts`'s now-unused `createDoneTask` was deleted. `/task` (status `todo`) remains the only way to create a task inline.
- **Added `/tag`** — a new read-only filter command, following the `/project`/`/team` pattern. `types.ts`'s `LogNote` gained a `tags: string[]` field (Obsidian's own combined frontmatter-`tags` + inline-`#tags` set, not part of `NoteFrontmatter` since the plugin never writes it); `note-store.ts`'s `loadNotes()` populates it via `getAllTags()` off the metadata cache. `filters.ts`'s `FilterState` gained a multi-select `tags` array, AND-combined like `projects`/`teams`. `dock.ts` gained the `/tag` command (autocompletes from every tag in use, via a new `getAllTags()` callback) and a tag filter chip; `Backspace`-to-remove-most-recent-filter priority is now project → team → tag → type → type attribute.
- **Fixed `/type`'s second step** — `dock.ts` previously gated "am I picking a type or its attribute?" on a sticky `pendingType` field that was only ever set inside `showTypeList`'s `select()` handler, not re-derived from the actually-typed text. Typing `/type meeting ` by hand (rather than clicking the dropdown) left `pendingType` null, so it kept re-running the type-name fuzzy match against the literal string `"meeting "` (trailing space included) — which never matches anything, so the attribute dropdown stayed empty. Conversely, once `pendingType` *had* been set by a prior selection, it stayed set even after backspacing the type name back out, so an empty `/type ` would incorrectly show the previous type's attribute list. Fixed by deriving the type/attribute split fresh from the current input on every keystroke (first space inside the argument separates the type name from the attribute query) instead of trusting leftover state from a previous selection.

Manual QA in a live vault is still outstanding for this phase: `/tag` autocomplete and filtering against notes with both frontmatter and inline tags, the new chip's removal (click and `Backspace`), and the `/type` two-step flow typed by hand end-to-end for both task/design (`status`) and meeting (`subtype`).

Manual QA in a live vault is still outstanding (see the note at the top of this file): Save button under various focus states, change-type round-trips between all six types (check dropped/defaulted fields match design.md's table), pin toggle staging + section transition only on collapse, pinned section surviving filters and the history-window cutoff.

## Status: done — Phase 26 (creation commands in Obsidian's command palette)

`design.md` §7 now documents this. The seven creation commands (`/draft`, `/task`, `/meeting`, `/recurring`, `/thoughts`, `/knowledge`, `/design`) are mirrored as standalone, hotkey-bindable entries in Obsidian's own command palette, reachable without the Logbook view already being open. Implementation reuses the existing dock flow rather than building a second UI:

- `dock.ts`'s already-private `pickCommand(key)` (prefills `/<key> `, focuses the input, re-runs `onInput()` — what clicking a command in its own dropdown already does) gained a public `runCommand(key)` wrapper.
- `LogbookView.ts` gained `focusDockCommand(key)`, a one-line passthrough to `this.dock.runCommand(key)`, mirroring how `closeActiveCard()` already exposes a public entry point for `main.ts`'s global `Mod+Enter` command.
- `main.ts` builds a `CREATION_COMMANDS` list off `ALL_COMMANDS` (the six `NOTE_TYPES`) plus a manual `recurring` entry, and registers one `addCommand` per type: each reveals/opens the Logbook view via `activateView()` (now returning the `LogbookView` instance instead of `void`) and calls `view.focusDockCommand(key)`.

## Status: done — Phase 27 (split meeting/recurring into separate types; dropped `theme`/`template`)

`design.md` §2, §4, §5, §7, §8, §14, §15 now document this. The previous `meeting` type carried a `subtype: standalone | recurring` discriminator plus an optional `theme` and `template`; `recurring` is now its own first-class `NoteType`, `meeting` keeps only standalone-shaped notes, and `theme`/`template` are gone entirely:

- **`types.ts`** — `NoteType` gained `"recurring"`; `MeetingSubtype` removed. New `MeetingAgenda` union (`meetup | presentation | workshop | crisis | decision | other`) and `MEETING_AGENDAS` array. `MeetingFrontmatter` lost `subtype`/`theme`/`template`/`occurrences`, gained `agenda: MeetingAgenda`. New `RecurringFrontmatter` (`attendees[]`, `occurrences[]`) and `isRecurring()` predicate, added to the `NoteFrontmatter` union alongside the existing `is*` predicates. `NOTE_TYPES` gained a `recurring` entry (no `filterAttr`) and `meeting`'s `filterAttr` moved from `subtype` to `agenda`. `convertType()` and `activityTimestamp()` updated for the new shapes (the latter now keys off `isRecurring(n) && n.fm.occurrences.length` instead of `isMeeting(n) && fm.subtype === "recurring"`).
- **`note-store.ts`** — `createNote()`'s meeting branch writes `agenda: meetup` instead of `subtype: standalone`; a new `recurring` branch writes just `attendees: []`. `createRecurringMeeting()` now creates a `type: recurring` note instead of a `meeting` note with `subtype` patched on afterward. `addOrFindTodayOccurrence()` takes a `RecurringFrontmatter` and no longer consults a template. `normalizeFrontmatter()` got a dedicated `recurring` case and a slimmed-down `meeting` case. Deleted entirely: `listTemplates()`, `getTemplateHeadings()`, `setMeetingTemplate()`, the `scaffoldBody()` helper, and `insertOccurrenceHeading()`'s now-unused `headingLines` parameter. `loadNotes()`'s `raw.type === "template"` skip-guard is gone along with the subsystem it supported.
- **`filters.ts`** — `fieldsOf()`'s meeting case now indexes `fm.agenda` instead of `fm.theme`; a new `recurring` case indexes just `attendees`.
- **`LogbookView.ts`** — `typeAttrValues()`'s meeting case returns `MEETING_AGENDAS`; `recurringMeetings()` filters on `n.fm.type === "recurring"` instead of the old subtype check; `handleOccurrence()`'s guard is `note.fm.type !== "recurring"`. `createAndShow()` dropped its `opts?: { recurring?: boolean }` parameter and branches directly on `type === "recurring"` (both call sites — `onCreate`/`onCreateRecurring` — now just pass a `NoteType` including `"recurring"` itself). The `templateTitles` field, its `refresh()` population, and the `templates` pool callback are gone.
- **`card.ts`** — `CardContext.pools` lost `templates()`. `commit()` lost its `templateDirty`-driven `setMeetingTemplate` branch and the `templateDirty` flag itself. `renderTypeFields()` lost the meeting-only theme input and template input/datalist block (and the `markTemplateDirty` callback parameter that fed it); its attendees picker now fires for `isMeeting(note) || isRecurring(note)` instead of being nested under a meeting-only block. `refreshTypeDependentUI()`'s occurrence-info condition is `isRecurring(note)` instead of `isMeeting(note) && fm.subtype === "recurring"`. `renderFilterAttrPill()`'s meeting branch renders `fm.agenda` under a new `.logbook-agenda-pill` class instead of `fm.subtype`/`.logbook-subtype-pill`.
- **`dock.ts`** — `showCommandList()`'s hand-rolled `recurring` array (needed when `recurring` wasn't a real `NoteType` yet) is gone now that `ALL_COMMANDS` includes it natively; `handleEnter()`'s `cmdKey === "recurring"` branch (routing to `onCreateRecurring`/`createRecurringMeeting` instead of the generic `createNote` path) is unchanged and still checked before the generic `NOTE_TYPES[cmdKey]` branch, so there's no double-handling now that `recurring` also satisfies that check.
- **`main.ts`** — `CREATION_COMMANDS` is now a plain `ALL_COMMANDS.map(...)` with no manual `recurring` append, since `recurring` is already in `NOTE_TYPES`/`ALL_COMMANDS`.
- **`styles.css`** — replaced the binary `.logbook-subtype-pill.is-recurring` rule with a value-agnostic `.logbook-agenda-pill` rule (same card-type-color tint, applied uniformly across all six agenda values rather than singling one out).

**Known gap, deliberately not addressed:** no migration tooling was written for vault data in the old schema. A pre-existing recurring meeting (`type: meeting`, `subtype: recurring`) will load and render as a plain (non-recurring) meeting card with no occurrence info, agenda defaulted to `meetup`, and its `theme`/`template` values silently dropped — `occurrences[]` stays in frontmatter but nothing reads it anymore. A pre-existing `type: template` marker note will load and render as a `draft` (the catch-all in `normalizeFrontmatter`'s switch), since the `type: template` skip-guard that used to hide it from the feed is gone along with the rest of the template subsystem. Anyone with such notes in their vault needs to manually re-create them as `type: recurring` notes (and re-type/re-tag former templates) after upgrading.

Manual QA in a live vault is still outstanding for this phase: creating a meeting and a recurring meeting via both `/meeting`/`/recurring` and their command-palette entries, the agenda pill rendering/filtering across all six values, `/occurrence` against a `type: recurring` note, change-type round-trips into and out of `recurring` (including the dropped-occurrences warning above), and confirming no leftover `theme`/`template`/`subtype` fields resurface anywhere in the UI for newly created notes.

Filter commands (`/project`/`/team`/`/tag`/`/type`/`/clear`) and `/occurrence` were deliberately left out of the command palette — they only act on a feed that's already in view, so there's no payoff to firing them from elsewhere in the vault, unlike creation which is a quick-capture action.
